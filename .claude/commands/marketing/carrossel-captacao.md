# /carrossel-captacao — Carrossel de Captação de Lead via Comentário

Skill para criar carrosséis no formato de captação de lead com comentário de palavra-chave. Formato mapeado de referências reais de alta performance. Referências completas em `.claude/commands/marketing/carrossel-refs/captacao-refs.md`.

---

## O que é esse formato

Carrossel curto (5-8 slides) que:
1. Identifica uma dor específica da persona com uma frase em aspas
2. Apresenta um método/sistema como resposta
3. Entrega uma amostra real do conteúdo
4. Usa prova social com nome + número + print
5. Converte o engajamento em lead via comentário com palavra-chave

**Não é carrossel educacional.** É carrossel de conversão com entrega de material. O objetivo é comentário → DM → lead qualificado.

---

## Antes de escrever

Perguntar ao usuário:

> "Pra montar esse carrossel, preciso de:
> 1. **Dor específica da persona** — que frase ela diria sobre o problema? (ex: 'não sei como fazer X')
> 2. **Método/solução** — qual é o sistema ou ferramenta que resolve isso?
> 3. **Entregável** — o que vai enviar no DM? (lista, script, estrutura, vídeo, documento)
> 4. **Palavra-chave do comentário** — ex: VRD1, GUPY1, CV1 (sigla + número)
> 5. **Case** — tem algum mentorado com resultado específico usando isso? (nome, resultado em R$ ou vagas, prazo)
> 6. **Amostra** — tem um exemplo concreto do conteúdo que pode mostrar num slide? (ex: uma pergunta do script, um item da lista)"

Se o usuário não tiver case ainda: criar o carrossel sem o slide de prova social e avisar que o formato fica mais fraco sem ele.

## Estrutura do carrossel

### Slide 1 — Hook: dor em aspas

**Obrigatório:** A frase precisa estar entre aspas. É a voz da persona, não do criador.

```
"[Frase que a persona diria sobre o problema]"
```

**Regras:**
- Frase que a persona já disse pra si mesma ou pra alguém
- Específica o suficiente para filtrar quem não tem essa dor
- Nunca genérica ("não consigo resultados") — sempre com contexto ("não consigo resposta dos recrutadores no Gupy")
- O criador não aparece neste slide. É só a frase.

**Variantes testadas:**
- Dor simples: `"Não sei como [fazer X]"`
- Dor de quem já tenta: `"Eu [faço X] mas [Y não acontece]"`
- Dor + réplica irônica: `"[Crença limitante]"` + `Ah, não?...` (mais confrontador, gera mais salvamentos)

**Para a Conectaria, exemplos de hooks:**
- `"Mando currículo mas não recebo nem retorno"`
- `"Tenho experiência mas não passo do Gupy"`
- `"Consigo entrevista mas não recebo proposta"`
- `"Não sei como colocar meu cargo no LinkedIn sem parecer genérico"`

---

### Slide 2 — Solução nomeada + prova visual

Apresenta o método/sistema com uma ferramenta visual (documento aberto, framework no Miro, planilha).

```
Eu [uso/fiz/gosto de usar] um [nome do método/sistema/ferramenta] que [resultado direto]
```

**Regras:**
- "Eu" inicia o slide — é autoridade pessoal, não genérica
- Nomear o método quando possível ("método VRD", "script de qualificação", "anatomia do currículo")
- A foto/visual de suporte deve mostrar algo real: documento aberto, tela do computador, framework desenhado
- "Simples" é uma palavra que reduz resistência — usar quando verdadeiro

**Para a Conectaria:**
- O método VRD (Verbo + Resultado + Descrição) é o ativo central — nomear sempre assim
- Mostrar o Google Doc do VRD, o modelo de currículo, o perfil otimizado como prova visual

---

### Slide 3 — Mecanismo ou etapa 1 (com CTA antecipado opcional)

Explica o "como" ou abre o processo. Se o carrossel for de método em etapas, este slide é a etapa 1.

```
[Explica o que faz / a lógica por trás]
(comenta [PALAVRA-CHAVE] se quiser [o entregável])
```

**Regras:**
- O parêntese com CTA é opcional aqui, mas recomendado — captura quem já está convencido sem esperar o final
- Se for dar um exemplo concreto, dar um (não três). Especificidade > quantidade
- Se tiver uma objeção óbvia embutida, quebrá-la no parêntese: "(dá pra fazer sem [objeção])"

---

### Slide 4 — Amostra real do conteúdo (opcional mas poderoso)

Dá um gostinho do que vai ser entregue. Cria credibilidade antes da prova social.

```
[Exemplo concreto — uma pergunta do script, um item da lista, uma linha do método]
```

**Regras:**
- Uma amostra específica vale mais do que descrever o que está no material
- Não entregar tudo — só o suficiente para provar que o material existe e tem substância
- Para a Conectaria: mostrar um exemplo de frase com VRD, uma linha de currículo antes/depois, uma pergunta de triagem de vaga

---

### Slide 5 — Prova social com case + print

```
[Nome] [verbo no passado] e [resultado com número]
```

**Com print de conversa real embaixo.**

**Regras do case:**
- Nome real (primeiro nome é suficiente)
- Resultado específico: número de vagas, R$ de aumento, tempo para recolocação, nível do cargo alcançado
- Prazo quando possível: "em 3 semanas", "em 45 dias"
- Print: de preferência do grupo de mentoria (mais crível que print de conversa individual)
- A frase do mentorado no print deve ser espontânea, não estruturada — autenticidade acima de tudo

**Sintaxe validada:**
- `O [Nome] [usou o método/fez isso] e [resultado]`
- `A [Nome] [verbo] e [resultado] em [prazo]`
- `[Nome] saiu de [situação anterior] pra [situação nova] em [tempo]`

**Para a Conectaria — métricas que funcionam:**
- Número de vagas abertas no Gupy após otimização
- Tempo de recolocação (em dias/semanas)
- Nível do cargo (de analista para gerente, de estagiário para pleno)
- Aumento salarial em % ou R$
- "Recebeu proposta em [X] dias após otimizar"

---

### Slide final — CTA com entregável prometido

```
Comenta [PALAVRA-CHAVE] que te envio [o entregável] no direct
```

**Variantes:**
- `...que te envio os processos pra copiar e colar`
- `...que eu te mando [o material] direto aqui`
- Com foto pessoal olhando para a câmera — aumenta conversão

**Regras:**
- A palavra-chave deve ser específica e fácil de lembrar (sigla do tema + número)
- O entregável precisa ser nomeado com precisão — não "um material", mas "o modelo de currículo", "o script VRD", "a checklist do Gupy"
- "Copiar e colar" é a promessa de menor esforço possível — usar quando verdadeiro

## Variantes de formato

### Formato A — Método em etapas (3-4 slides de processo)
Para quando o sistema tem passos sequenciais. Slides 3, 4 e 5 mostram etapas numeradas implicitamente. Termina com case.

Melhor para: ensinar um processo completo (ex: como otimizar currículo do zero).

### Formato B — Quebra de mito (confronto + jornada + resolução)
Hook com crença limitante + réplica irônica (`Ah, não?...`). Abre com confronto, concede no meio ("confesso que X é bom, massss"), resolve no final. Gera mais salvamentos.

Melhor para: quando a persona tem uma crença que precisa ser derrubada antes de aceitar o método.

### Formato C — Tática única com amostra
Foca em uma tática específica (não um sistema inteiro). Dá exemplo concreto no meio. CTA duplo (slide 3 e slide final).

Melhor para: entregar algo aplicável imediatamente (um script, uma pergunta, um modelo de frase).

### Formato D — Rotina/hábito pessoal
Tom de "eu gosto de fazer X" em vez de "faça X". Inclui detalhe humano que prova comprometimento. Entregável é vídeo ou gravação de tela.

Melhor para: quando o diferencial é a rotina do criador, não um método documentado.

## Mecânicas que fazem funcionar

### 1. Hook de aspas filtra a persona certa
Só quem já pensou exatamente aquela frase para no feed. Não é para todo mundo — é para quem tem aquela dor específica. Quanto mais específica a frase, mais qualificado o lead que comenta.

### 2. Visual de prova antes de qualquer afirmação
Mostrar o documento/ferramenta antes de afirmar que funciona. O leitor vê antes de acreditar. Reduz ceticismo.

### 3. CTA antecipado captura leads sem esperar o final
Inserir o CTA no slide 3 ou 4 captura quem já está convencido. Quem não comenta ainda continua — o CTA final existe para eles.

### 4. Amostra concreta = credibilidade antes do case
Uma pergunta do script, um item da lista, uma linha do método. Prova que o material existe antes de mostrar quem usou.

### 5. Case com trifecta: nome + número + print
Nome: identidade real. Número: resultado concreto. Print: prova que aconteceu. Qualquer um dos três isolado é fraco. Os três juntos eliminam a dúvida.

### 6. Palavra-chave alimenta o algoritmo e cria lista de leads
Todo comentário com a palavra-chave é sinal de engajamento para o algoritmo E um lead identificado para o DM. Dupla função.

### 7. Entregável específico remove fricção
"Te envio o modelo" é diferente de "te envio um material". Nomear o entregável remove a dúvida do que a pessoa vai receber.

## Palavras-chave para a Conectaria

Criar siglas que façam sentido para o tema:

| Tema | Sugestão de palavra-chave |
|---|---|
| Currículo / VRD | VRD1, CV1, MOD1 |
| Gupy / parser | GUPY1, ATS1 |
| LinkedIn | LK1, PERFIL1 |
| Entrevista | ENT1, RH1 |
| Negociação de salário | SAL1, NEG1 |
| Recolocação completa | REC1, JOGO1 |

---

## Checklist antes de publicar

- [ ] Hook está em aspas e é específico o suficiente para filtrar
- [ ] Visual de suporte é real (não mockup genérico)
- [ ] CTA aparece pelo menos duas vezes (slide 3-4 e slide final)
- [ ] Case tem nome real + número + print
- [ ] Entregável está nomeado com precisão
- [ ] Palavra-chave é fácil de lembrar e digitar
- [ ] Nenhum slide usa "transformador", "incrível", "revolucionário" ou qualquer hipérbole de IA
- [ ] Tom é de praticante compartilhando rotina, não de professor ensinando
